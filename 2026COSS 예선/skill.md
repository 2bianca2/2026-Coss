# 소프트웨어 기법 정리 (skill.md)

ATmega128(4KB SRAM, 128KB Flash, FPU 없음)이라는 작은 MCU 위에서 듀얼채널 오실로스코프를
bare-metal로 구현하기 위해 사용한 소프트웨어 기법을 전부 정리한 문서입니다. 코드 전체를
다시 훑어보며 실제로 쓰인 것만 적었습니다. 각 항목에 해당 코드 위치를 같이 표기했습니다.

---

## 1. 레지스터 직접 제어 (Bare-Metal)

라이브러리(Arduino, HAL 등) 없이 ATmega128 레지스터를 직접 read/write.

- **ADC**: `ADMUX`, `ADCSRA`, `ADCL`/`ADCH` 직접 제어 (`adc.c`) — 기준전압, MUX 채널,
  프리스케일러, 인터럽트 활성화를 전부 비트 단위로 설정.
- **타이머**: `TCCR0/OCR0`(Timer0, millis용), `TCCR1A/TCCR1B/OCR1A`(Timer1, 샘플링 클럭)를
  CTC 모드로 직접 구성.
- **SPI**: `SPCR`, `SPSR`, `SPDR` 직접 제어 (`spi.c`) — Mode 0, Master, F_CPU/4.
- **GPIO**: `DDRx`/`PORTx`/`PINx` 직접 조작 — LCD 제어선(DC/RST/CS), 74HC165 PL핀,
  ADC 입력핀 설정 전부 포함.
- **EEPROM**: `avr/eeprom.h`의 `eeprom_read_byte/block`, `eeprom_write_byte/block`으로
  캘리브레이션 값을 저장/복원 (`calib.c`).
- **인터럽트**: `ISR(TIMER0_COMP_vect)`, `ISR(TIMER1_COMPA_vect)`, `ISR(ADC_vect)` 3개를
  직접 작성해서 시간축 샘플링, ms 카운터를 하드웨어로 처리.

## 2. 하드웨어 리소스 제약 극복

### 2.1 SPI 버스 공유 문제 해결 (협조적 폴링)
74HC165(버튼/엔코더)와 ILI9488 LCD가 같은 SPI 버스(SCK/MISO)를 쓴다. LCD 전송 중간에
인터럽트로 74HC165를 읽으면 두 통신 다 깨진다. 그래서 인터럽트 기반 입력 읽기를 포기하고,
`waveform_draw()`가 파형을 그리는 긴 루프 안에서 몇 컬럼마다 한 번씩 콜백
(`waveform_poll_fn`)을 호출해 그 틈에 버튼/엔코더를 폴링한다. (`waveform.c`
`POLL_EVERY_N_COLS=2`, `app.c`의 `poll_input`이 이 콜백으로 전달됨)

### 2.2 ADC 1개로 2채널 동시 샘플링
ADC 하드웨어가 1개뿐이라 MUX로 채널을 전환하며 순서대로 변환. Timer1 COMPA 인터럽트가
"한 쌍(CH1+CH2)"의 시작만 알리고, `ADC_vect` 안에서 CH1 변환 완료 즉시 MUX를 CH2로 바꿔
곧바로 다음 변환을 시작한다 — 그래서 타이머 주기 = "채널당" 샘플 주기가 되어 샘플레이트가
반토막 나지 않는다. (`adc.c` `ISR(ADC_vect)`)

### 2.3 ADC 채널 전환 안정화 딜레이
MUX를 전환한 직후 바로 변환을 시작하면 ADC 내부 샘플홀드 커패시터가 이전 채널 전압을
아직 들고 있어 크로스토크가 생길 수 있다. MUX 전환 후 `_delay_us(10)`을 넣어 새 채널
전압으로 안정될 시간을 확보. (`adc.c` 152번째 줄 부근)

## 3. 동시성/레이스 컨디션 제어

### 3.1 핑퐁(더블) 버퍼링
ISR은 항상 "쓰기용" 버퍼에만 쓰고, 프레임이 다 차면 포인터만 바꿔치기해서(데이터 복사
없음) 방금 완성된 버퍼를 "읽기용"으로 내놓는다. 메인루프가 느긋하게 처리하는 동안 ISR이
같은 메모리를 덮어쓰는 레이스를 막기 위함. CH1/CH2 각각 A/B 두 버퍼씩 총 4개
(`capture_a_ch1`, `capture_b_ch1`, `capture_a_ch2`, `capture_b_ch2`)를 두고 포인터
변수(`adc_buffer_ch1/ch2`, `write_buf_ch1/ch2`)로 역할을 스왑. (`adc.c`)

### 3.2 중첩 카운터 락 (재진입 안전)
핑퐁 버퍼만으론 못 막는 구간이 있다 — 그리기가 캡처 한 바퀴(~19ms)보다 오래 걸리면
(30ms+) 읽는 도중에 ISR이 버퍼를 또 스왑해버릴 수 있음. `adc_read_lock()`/
`adc_read_unlock()`을 단순 0/1 플래그가 아니라 **중첩 카운터**로 구현 — `poll_input()`이
최상위 루프에서도 불리고 `waveform_draw()` 콜백으로 중첩되어서도 불리는데, 단순
플래그면 안쪽 unlock이 바깥쪽 락을 너무 일찍 풀어버리기 때문. 락이 걸려있으면 ISR은
스왑과 `adc_frame_ready` 설정을 건너뛰고 조용히 프레임 하나를 버린다(깨진 데이터를
보여주는 것보단 나음). (`adc.c` `adc_buf_lock_count`)

### 3.3 인터럽트 안전 읽기
`millis()`가 `uint32_t`(4바이트, AVR에서 원자적으로 못 읽음)를 읽을 때 `cli()`/`sei()`로
감싸서 인터럽트 도중 값이 찢어지는(torn read) 걸 방지. (`millis.c`)

### 3.4 지연 적용 패턴 (Deferred Apply)
`poll_input()`은 파형을 그리는 도중 콜백으로 불릴 수 있어서, 그리기 중인
`waveform_ch_t` 자체(레이아웃, 스케일)를 바로 바꾸면 위험하다. 그래서 UI 상태만 바꾸고
`ui_dirty` 플래그만 세운 뒤, 프레임을 다 그린 후 최상위 루프에서만 `apply_ui_changes()`가
실제 레이아웃/스케일/샘플링레이트 변경을 반영한다. (`app.c`)

## 4. 화면 렌더링 최적화

### 4.1 부분 갱신(Dirty Rectangle) 렌더링
파형(`waveform.c`)과 스펙트럼(`spectrum.c`) 둘 다, 화면 전체를 지웠다 다시 그리지 않고
**이전 프레임과 달라진 부분만** 지우고 다시 그린다. 파형은 컬럼별로 `prev_y0`/`prev_y1`/
`has_prev`를 기억해뒀다가 범위가 같으면 아예 건드리지 않고, 다르면 그 범위만 지운 뒤
격자를 복원(`grid_redraw_rect`)하고 새로 그린다. 스펙트럼도 막대별 이전 높이를 기억해서
줄어든 만큼만 지운다. 이 방식이 없으면 매 프레임 화면이 깜빡인다.

### 4.2 대각선 보간 (고정 SPI 비용)
샘플 사이를 사각형 하나로 통째로 채우면 값이 급격히 변하는 구간에서 파형이 대각선이
아니라 두꺼운 세로 블록처럼 보인다. `draw_diagonal_segment()`가 두 점 사이를 픽셀 단위가
아니라 **고정된 단계 수**(`DIAG_STEPS=3`)로만 선형보간해서, 값이 얼마나 튀든 SPI 전송
비용이 항상 일정하게 유지되도록 했다. (`waveform.c`)

### 4.3 화면 분할 추상화 (Region 기반 렌더링)
`scope_region_t`(y0, y1, v_divs)로 "그릴 영역"을 추상화해서, 같은 그리기 함수가 전체화면
(`REGION_FULL`)과 분할화면(`REGION_CH1_HALF`/`REGION_CH2_HALF`)을 구분 없이 처리한다.
`waveform_ch_t` 인스턴스를 채널마다 따로 둬서(재진입 가능한 구조) CH1/CH2가 동시에 독립적
으로 그려질 수 있다. (`grid.h`, `waveform.h`)

## 5. 입력 처리 기법

### 5.1 디바운스 vs Raw 폴링 분리
버튼은 2번 연속 같은 값이어야 "확정"으로 인정하는 디바운스(`input_debounce`)를 쓰지만,
엔코더는 raw 값을 그대로 쓴다 — 디바운스를 거치면 CLK/DT가 계속 바뀌는 회전 중엔 좀처럼
"확정"되지 않아 클릭이 씹히기 쉽기 때문. (`input.c`)

### 5.2 그레이코드 상태전이표 쿼드러처 디코딩
로터리 엔코더 방향 판별을 "CLK가 막 올라가는 순간 DT 하나만 찍는" 방식이 아니라, 표준
그레이코드 16칸 전이표(`QUAD_TRANSITION[16]`, PROGMEM)로 구현. `idx = (prev_state<<2) |
cur_state`로 이전→현재 상태 전이를 찾아 ±1/0을 누적하고, 디텐트 한 칸(4스텝)이 다 쌓여야
방향을 확정한다. 폴링 타이밍이 불규칙해도(그리기 도중 콜백으로 호출되므로) 정확하게
동작하도록 설계됨. (`input.c`)

### 5.3 롱프레스/숏프레스 판정
`millis()` 기반으로 버튼을 누른 시점을 기록해뒀다가, 1.5초 이상 유지되면 롱프레스로
판정(캘리브레이션 진입, 트리거 on/off), 그 전에 떼면 숏프레스로 판정(채널 on/off,
RUN/STOP)하는 상태머신을 3개 버튼(SW1/SW3/SW4) 각각에 대해 구현. (`app.c`)

## 6. 신호 처리 / 계측 알고리즘

### 6.1 적응형 기준선 제로크로싱 트리거/주기 측정
신호가 한쪽으로 치우쳐 고정 0V를 안 지나가는 경우(RC 충방전 곡선 등)에도 동작하도록,
기준선을 고정 0V가 아니라 **그 프레임(또는 마진 구간)의 (최댓값+최솟값)/2**로 매번
다시 잡는다. 실제 오실로스코프의 auto-level 트리거와 같은 방식. 트리거 탐색
(`adc_find_trigger`, `adc.c`)과 주기 측정(`find_period_us`, `statusbar.c`) 둘 다 이
방식을 쓴다.

### 6.2 Q8 고정소수점 선형보간 (서브샘플 정밀도)
제로크로싱이 두 샘플 사이 어딘가에서 일어나므로, 정수 샘플 인덱스만으론 정밀도가
부족하다. `frac_q8 = (0-prev_mv)*256/(cur_mv-prev_mv)`로 샘플 사이의 정확한 교차
위치를 Q8 고정소수점(256분의 1 단위)으로 계산해서 FREQ/PERIOD 정밀도를 높였다.
(`statusbar.c` `find_period_us`)

### 6.3 2점 캘리브레이션
GND(0V)와 +5V 기준전압, 두 점에서 raw ADC값을 측정해 `mv = (raw-zero_raw)*5000/
(ref_raw-zero_raw)` 선형 변환식을 구성. 미보정 상태에서는 이상적 계산식
(`adc_raw_to_mv`)으로 폴백. EEPROM에 매직바이트와 함께 저장해서 전원을 꺼도 유지.
(`calib.c`)

### 6.4 자동 트리거 + 폴백 (Auto-trigger)
버튼으로 트리거 레벨을 수동 설정하는 대신, 매 프레임 자동으로 제로크로싱을 찾고
(`adc_find_trigger`), 못 찾으면 조용히 가장 최근 구간으로 폴백해서 항상 뭔가를 보여준다.
트리거 성공 여부(`adc_trigger_locked`)는 상태바에 TRIG/SEARCH로 표시. 트리거 자체는
SW1 롱프레스로 켜고 끌 수 있음(꺼지면 폴백 로직만 항상 사용).

## 7. FFT (고정소수점 신호처리)

### 7.1 Radix-2 DIT FFT (반복형, in-place)
64포인트 Cooley-Tukey 방식 FFT를 재귀 없이 반복문으로 구현(`bit_reverse` 비트반전
정렬 → 6단계(`FFT_STAGES = log2(64)`) 버터플라이 연산). AVR의 제한된 스택 공간에서
재귀 호출 오버헤드를 피하기 위해 반복형으로 작성. (`fft.c`)

### 7.2 삼각함수 룩업 테이블 (Twiddle Factor LUT)
AVR엔 FPU가 없어서 `sin()`/`cos()`를 매 버터플라이(총 192회)마다 계산하면 감당이 안
된다. 64포인트에 필요한 코사인/사인 값을 Q15 고정소수점(±32767=±1.0)으로 미리 계산해
`FFT_COS`/`FFT_SIN` 배열에 저장하고 PROGMEM(플래시)에 둬서 `pgm_read_word()`로 읽는다.

### 7.3 Q15 고정소수점 연산 + 오버플로 방지 스케일링
부동소수점 대신 정수 곱셈(`q15_mul`: `(a*b)>>15`)으로 트위들 곱셈을 처리. 버터플라이
덧셈이 매 스테이지 최대 2배까지 커질 수 있어(6단계 누적 시 int16 범위 초과) 매
스테이지마다 결과를 절반으로 스케일(`>>1`)해서 오버플로를 방지 — 절대값이 아니라
상대적 진폭만 필요하므로 스케일 손실은 무해함.

### 7.4 정수 제곱근 (이진 탐색)
진폭 크기(`sqrt(re²+im²)`)를 구할 때 `sqrt()`(부동소수점) 대신 이진 탐색 기반 정수
제곱근(`isqrt32`)을 사용 — `fft.c`와 `statusbar.c`(RMS 계산) 양쪽에서 같은 기법을 씀.

### 7.5 메모리 절약을 위한 채널 공유 작업버퍼
FFT는 채널 하나만 켜진 전체화면일 때만 동작하도록 UI를 제한해서, CH1/CH2용 작업버퍼를
따로 안 두고 `work_re`/`work_im` 하나만 공용으로 써서 SRAM을 절약. FFT 크기(`FFT_N=64`)
도 파형 표시용 샘플 수(`ADC_BUFFER_SIZE=96`)와 독립적으로 고정 — radix-2 FFT가 2의
거듭제곱을 요구해서 96에 맞출 수 없기 때문에, 96개 중 앞 64개만 사용.

## 8. 메모리 최적화 (4KB SRAM 안에 담기)

### 8.1 PROGMEM으로 상수 데이터를 플래시에 고정
AVR(하버드 구조)은 `const`만으론 플래시에 안 가고 기본적으로 SRAM에도 복사된다(일반
포인터 역참조가 SRAM만 읽을 수 있어서). `PROGMEM` 속성으로 명시적으로 플래시에만 두고,
`pgm_read_byte/word/dword()`, `strncpy_P()`, `snprintf_P()`, `PSTR()`로 읽도록 전
코드베이스에 일관되게 적용:
- 상태바/캘리브레이션/스펙트럼의 모든 UI 문자열
- 측정항목 이름(`MEASURE_NAMES`), V/DIV·T/DIV 표시 문자열(`VOLT_DIV_STR`/`TIME_DIV_STR`)
  — 문자열 내용뿐 아니라 **포인터 배열 자체**도 PROGMEM에 둬서 이중으로 절약
- V/DIV·T/DIV 숫자 테이블(`VOLT_PER_DIV_MV`, `TIME_PER_DIV_US`)
- 그레이코드 전이표(`QUAD_TRANSITION`), FFT 트위들 팩터(`FFT_COS`/`FFT_SIN`), 5x7
  비트맵 폰트(`font5x7`)

이 작업 하나로 SRAM 사용량을 약 580바이트 절감(여유 747→1327바이트).

### 8.2 스택 사용량 정적 분석
`avr-gcc -fstack-usage`로 함수별 스택 프레임 크기를 뽑아서, 가장 깊은 실제 호출 체인
(`app_run_frame → waveform_draw → poll_input → statusbar_draw_full → draw_channel_row
→ draw_measure_value → find_period_us`)을 따라 합산 — 인터럽트 프레임과 `snprintf`
내부 사용량까지 감안해서 "실제로 안전한 SRAM 여유가 얼마나 남는지"를 근거를 갖고
판단(추정치를 기반으로 버퍼 크기를 늘릴지 말지 결정).

### 8.3 죽은 코드 제거
쓰지 않는 UART 드라이버(`uart.c`/`uart.h`)를 완전히 제거해서 `FILE`/`stdout` 관련
avr-libc 내부 구조체(`__iob` 등)가 딸려 들어오는 것까지 같이 제거.

### 8.4 핑퐁 버퍼 크기와 샘플레이트의 트레이드오프 설계
`ADC_BUFFER_SIZE`(화면 표시 샘플 수)를 늘리면 같은 T/DIV에서 샘플레이트가 올라가
나이퀴스트 여유가 커지지만, 캡처 버퍼(4개)와 파형 dirty-tracking 배열이 전부
비례해서 커진다. PROGMEM 최적화로 확보한 여유 안에서 64→96으로 늘리되, FFT처럼 2의
거듭제곱이 필요한 부분은 독립적으로 유지하는 식으로 메모리 예산과 성능을 같이 맞춤.

## 9. 아키텍처/설계 기법

### 9.1 계층 분리
`main.c`(엔트리포인트, 하드웨어 init 순서만) → `app.c`(애플리케이션 오케스트레이션,
UI 상태 소유) → 도메인 모듈(`adc`/`waveform`/`spectrum`/`fft`/`calib`/`ui`/`statusbar`/
`grid`) → 하드웨어 드라이버(`display`/`text`/`spi`/`hc165`/`millis`)로 계층을 나눠서
각 모듈이 자기 책임만 지도록 구성.

### 9.2 콜백 함수 포인터 패턴
`waveform_poll_fn`(`void(*)(void)`) 타입으로 "그리는 도중 호출할 함수"를 파라미터로
받아서, `waveform.c`가 `app.c`의 구체적인 폴링 로직을 몰라도 되게 분리(의존성 역전).

### 9.3 재진입 가능한 구조체 인스턴스
`waveform_ch_t` 하나로 CH1/CH2 양쪽 상태(그리기 영역, 스케일, dirty-tracking)를 표현할
수 있게 설계해서, 전역변수 하나 공유 없이 `wf_ch1`/`wf_ch2` 두 인스턴스로 완전히 독립된
채널 두 개를 같은 코드로 처리.

### 9.4 실시간 제약을 고려한 버튼-그래픽 우선순위 설계
"빠른 T/DIV에서 프레임이 초당 수백 번 들어올 수 있는데, 그때마다 화면을 다시 그리면
입력 폴링 시간을 다 잡아먹는다"는 문제를, 샘플링은 최대한 빠르게 유지하면서 실제 **화면
갱신만** `MIN_REDRAW_MS=30`(약 33Hz)로 속도 제한하는 방식으로 해결 — 데이터 정확도와
UI 반응성을 분리해서 둘 다 확보.
